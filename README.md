# ВСМ Тренажёр

Геймифицированный тренажёр для проводников высокоскоростной магистрали Москва — Санкт-Петербург.
Сотрудник проходит нештатные ситуации на борту, решает под таймером, видит последствия по двум шкалам
(«Лояльность пассажира» и «Рейтинг безопасности») и получает очки компетенций, уровни, достижения и место в рейтинге.
После каждого сценария открывается разбор каждого решения: что выбрано, почему это хорошо или плохо, как было бы лучше, какой регламент применяется.

> Решение для кейса «Геймификация для ВСМ», Хакатон Московского транспорта.
> Все данные в демо-среде синтетические (152-ФЗ).

**Демо-стенд:** http://103.88.241.174:8080 (логин `demo`, пароль `vsm2026`; другие учётные записи — в разделе «Демо-доступ»).

## Возможности

| | |
|---|---|
| **Движок сценариев** | Нелинейные диалоги в YAML: условные переходы по шкалам, флагам и переменным, условия доступности вариантов, прерывания при падении шкалы, серверный таймер с отдельной веткой «не успел» |
| **Две шкалы** | Каждое решение по-разному меняет лояльность и безопасность, от шкал зависит сюжет и финал |
| **7 сценариев** | Плохо с пассажиром · пьяный пассажир · вейп в салоне · два пассажира на одно место · бесхозная вещь · потерялся ребёнок · пассажир на кресле-коляске |
| **Геймификация** | Очки опыта и 7 уровней, баллы рейтинга, которые сгорают через 30 дней, 14 достижений, челленджи, рейтинг по бригаде / депо / компании, уведомления |
| **Обратная связь** | Разбор каждого решения с объяснением и лучшими вариантами, покрытие ролевой модели «Признать → Правило → Решение → Заверить» |
| **Аналитика** | Мастерство по 7 компетенциям, проседающие компетенции, текстовые выводы, рекомендации; для тренера: тепловая карта бригад, самые сложные решения, drill-down по сотруднику |
| **Интеграция** | REST API + Swagger, API для HR/LMS по ключу: синхронизация сотрудников, результаты, журнал решений в формате xAPI |
| **Визуальный редактор** | Граф решений (React Flow), связи перетаскиванием, конструктор условий и эффектов, проверка на лету с подсветкой узлов, тестовый прогон черновика, отмена/повтор, импорт/экспорт YAML, публикация без перезапуска |
| **Расширяемость** | Новый сценарий, достижение или челлендж добавляется в редакторе, YAML-файлом или через API, без правки кода |

## Быстрый старт

### Вариант 1: Docker (рекомендуется)

```bash
docker compose up --build
```

Откройте http://localhost:8080. Swagger: http://localhost:8080/docs.

### Вариант 2: локально (Python 3.12+, Node.js 20+)

```bash
# backend
cd backend
python -m venv .venv
.venv\Scripts\activate            # Windows;  source .venv/bin/activate — Linux/macOS
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000

# frontend (в другом терминале)
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173. Swagger: http://localhost:8000/docs.

При первом запуске создаётся база SQLite (`backend/vsm.db`), загружаются сценарии и синтетические демо-данные:
16 проводников в 4 бригадах с историей прохождений. Чтобы начать с чистого листа, удалите `vsm.db`.

### Демо-доступ

| Логин | Пароль | Роль |
|---|---|---|
| `demo` | `vsm2026` | Проводник (Бригада М-1). У части баллов скоро истекает срок, поэтому видно предупреждение |
| `trainer` | `vsm2026` | Тренер: аналитика команды, визуальный редактор сценариев (Команда → Сценарии) |
| `igor`, `maria`, `ekaterina`, … | `vsm2026` | Другие проводники (`backend/content/demo_org.yaml`) |

Ключ API интеграции: заголовок `X-API-Key: demo-integration-key`.

## Развёртывание в облаке (демо-стенд)

Frontend — на Vercel, backend — на Render.com. Vercel проксирует `/api/*`, `/docs` и `/openapi.json`
на backend (`frontend/vercel.json`), поэтому для браузера всё работает с одного домена и CORS не нужен.

1. **Backend.** На https://render.com: *New → Blueprint* → выбрать этот репозиторий. Render прочитает `render.yaml`
   и создаст сервис `vsm-trainer-api`: Python 3.12, регион Frankfurt, секрет JWT генерируется автоматически.
   Проверка: `https://<сервис>.onrender.com/api/health` → `{"status":"ok"}`.
2. **Адрес backend.** Если Render выдал адрес не `https://vsm-trainer-api.onrender.com`, замените его в `frontend/vercel.json`.
3. **Frontend.** Проект Vercel с корнем `frontend` (Framework: Vite). Переменные окружения не нужны.

На бесплатном тарифе Render сервис засыпает после 15 минут без запросов, первый запрос после паузы
обрабатывается до минуты. База SQLite не сохраняется между перезапусками: демо-данные создаются заново.

## Тесты и проверки

```bash
cd backend
pytest                              # 80 тестов: движок, баланс сценариев, сквозные API-сценарии, API редактора
python -m app.engine.validate       # проверка всех YAML-сценариев

cd frontend
npm test                            # 21 тест: модель визуального редактора, склонения (Vitest)
npm run lint                        # строгая проверка типов TypeScript
npm run build
```

## Структура

```
backend/
  app/engine/        ядро: формат сценариев, условия, исполнение, подсчёт, разбор
  app/gamification/  уровни, баллы, достижения, челленджи, рейтинг, уведомления
  app/analytics/     мастерство, выводы, рекомендации, командная аналитика
  app/api/           REST API (FastAPI)
  content/           ДАННЫЕ: сценарии, компетенции, достижения, челленджи, уровни, демо-оргструктура
  tests/
frontend/src/        React + TypeScript, mobile-first; editor/ — визуальный редактор сценариев
docs/                документация
```
