# Ограничения решения и план развития

## Текущие ограничения

| Ограничение | Последствие | Как снять |
|---|---|---|
| Черновики редактора хранятся в браузере (localStorage), совместной работы нет | Черновик привязан к устройству | Серверные черновики, история версий с diff, комментарии методистов |
| 7 сценариев из 51 ситуации датасета | Не все ситуации покрыты | Наполнение контента (этап 1) |
| Схема БД создаётся через `create_all`, миграций нет | Изменение схемы требует пересоздания БД | Alembic |
| Счётчик неудачных входов хранится в памяти процесса | При нескольких экземплярах backend лимит считается отдельно на каждом | Redis |
| Уведомления приходят опросом раз в 30 с, только внутри приложения | Нет push-уведомлений на телефон | Web Push / корпоративный мессенджер |
| Аутентификация по логину и паролю | Нет единого входа | SSO (OIDC / Active Directory) |
| Интерфейс только на русском | Нет локализации | i18n |
| Нет офлайн-режима | Без сети тренажёр недоступен | PWA с офлайн-кешем сценариев |

## План развития

### Этап 1 — пилот (1–2 месяца)
- Редактор сценариев: серверные черновики и согласование (методист → тренер → публикация), сравнение версий, покрытие веток при прогоне («какие узлы ещё не проверены»).
- Покрыть сценариями все 51 ситуацию датасета и стандарты 03.011, 03.013, 03.014; сценарии по классам «первый» и «бизнес» с условиями `class == …`.
- Пилот на одной бригаде: сбор обратной связи, калибровка весов шкал и порогов мастерства.

### Этап 2 — интеграция (2–4 месяца)
- SSO, синхронизация оргструктуры с HR по расписанию, выгрузка в корпоративную LMS (xAPI LRS).
- Назначение обязательных сценариев тренером (например, после инцидента или перед запуском нового класса обслуживания).
- Push-уведомления, еженедельный дайджест прогресса.

### Этап 3 — развитие механик
- Сценарии-«смены»: цепочка инцидентов в одном рейсе Москва — Санкт-Петербург, где состояние переносится между ситуациями.
- Командные челленджи между бригадами и депо.
- Адаптивная сложность: подбор следующего сценария по проседающим компетенциям (основа — текущие рекомендации).
- Голосовой режим: ответ голосом, распознавание речи и оценка по ролевой модели.
- Медиа в узлах: иллюстрации и звук (объявления, рация) для большего погружения.
