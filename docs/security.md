# Безопасность и соответствие требованиям

## Персональные данные (152-ФЗ)

| Требование | Как выполнено |
|---|---|
| Нет реальных ПДн в демо-среде | Все сотрудники — синтетические псевдонимы с табельными номерами `SYN-xxxx` (`backend/content/demo_org.yaml`, помечено в файле). Пассажиры в сценариях обезличены («пассажир места 12C») |
| Минимизация данных | У сотрудника хранятся только логин, псевдоним (или сокращённое ФИО), табельный номер, роль, бригада, внешний id HR. Паспортных данных, телефонов и e-mail нет |
| Данные пассажиров | Система не собирает и не хранит данные пассажиров. Сценарии учат не раскрывать их: объявление о потерявшемся ребёнке без ПДн, диагноз пассажира не обсуждается с соседями |
| Нет ПДн в артефактах | В репозитории нет дампов БД (`*.db` в `.gitignore`), демо-данные генерируются при запуске |

## Секреты

- Секреты (`JWT_SECRET`, пароль БД, демо-ключ интеграции) задаются только переменными окружения; шаблон — `backend/.env.example`, сам `.env` исключён из git.
- При `APP_ENV=prod` приложение **не запустится** с секретом JWT по умолчанию (`Settings.check`).
- Пароли: PBKDF2-SHA256, 200 000 итераций, соль на пароль, сравнение за постоянное время.
- API-ключи интеграций хранятся только как SHA-256 хэш.

## Доступ

| Роль | Права |
|---|---|
| `conductor` | Свои попытки, профиль, аналитика; общий рейтинг (только псевдонимы и баллы) |
| `trainer` | Плюс командная аналитика, просмотр графов сценариев, загрузка сценариев |
| Внешняя система (`X-API-Key`) | Только `/integration/*` |

- Чужая попытка возвращает 404, а не 403: так нельзя узнать, существует ли объект.
- Во время прохождения клиент не получает оценки вариантов и обратную связь, правильный ответ нельзя подсмотреть в DevTools.
- Таймер проверяется на сервере: ответ позже дедлайна (с запасом 2 с) засчитывается как таймаут.
- Защита от перебора: не больше 5 неудачных входов в минуту на логин (ответ 429).
- Заголовки: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`. CORS ограничен списком адресов frontend.
- Backend в контейнере работает от непривилегированного пользователя.

## Предсказуемая обработка ошибок

- Единый формат `{"error": {"code", "message", "details"}}` для всех ошибок, включая ошибки валидации и 404.
- Некорректные действия отклоняются кодом 409 или 422 с понятным текстом: вариант недоступен, попытка уже завершена, ответ и таймаут одновременно, сценарий с битым графом.
- Необработанные исключения пишутся в лог сервера. Клиент получает только `internal_error`, без трассировок и SQL.
- Загружаемые сценарии разбираются через `yaml.safe_load` (без исполнения кода), условия разбираются без `eval`, лишние поля отклоняются, размер тела ограничен 200 КБ.
- Покрыто тестами: `backend/tests/test_api.py::test_invalid_actions_are_rejected_predictably` и другие.
