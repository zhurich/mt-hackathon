# Формат сценария (YAML DSL)

Сценарии лежат в `backend/content/scenarios/*.yaml`. При старте backend каждый файл валидируется
(`backend/app/engine/schema.py`) и загружается в БД. Ошибка в сценарии → понятное сообщение с указанием узла.
Проверить файл без запуска сервера: `python -m app.engine.validate content/scenarios/<файл>.yaml` (из папки `backend`).

Удобнее всего создавать и править сценарии в **визуальном редакторе** (Команда → Сценарии → «Создать» / «Редактировать»):
граф узлов, формы вместо ручного YAML, проверка на лету, тестовый прогон. Редактор умеет импортировать и выгружать этот же YAML.

Новый сценарий можно также загрузить через API: `POST /api/v1/scenarios` (роль `trainer`), тело — YAML или JSON.

## Пример целиком

```yaml
id: vape-smoking               # латиница, цифры, дефис; уникален
version: 1                      # увеличивайте при изменении — в БД обновится
title: Электронная сигарета в салоне
summary: Пассажир бизнес-класса курит вейп на своём месте.
category: safety                # medical | conflict | safety | service | accessibility
difficulty: 2                   # 1..3, влияет на бонус XP за исход
service_class: business         # standard | comfort | business | first
sources:                        # ссылки на регламенты — показываются в разборе
  - "Ситуации на борту, №20"
briefing: |
  Вагон 3, бизнес-класс. Рейс Москва — Санкт-Петербург, скорость 360 км/ч.
initial:
  loyalty: 70                   # 0..100
  safety: 60                    # 0..100
  vars:                         # числовые переменные сценария (необязательно)
    warnings: 0
hud:                            # переменные, которые видит игрок (необязательно)
  warnings: Предупреждений
start: start
interrupts:                     # проверяются после КАЖДОГО решения, по порядку; каждое срабатывает не более 1 раза
  - if: ["safety <= 15"]
    next: end_smoke_alarm
nodes:
  start:
    type: choice
    speaker: passenger          # narrator | passenger | chief | colleague | child | radio | system
    speaker_name: Пассажир места 4B
    text: Вы замечаете облако пара над креслом 4B...
    competencies: [safety, communication]
    timer: 25                   # секунд на решение (необязательно)
    on_timeout:                 # обязателен, если есть timer
      effects: { safety: -15 }
      feedback: Пока вы медлили, соседи начали возмущаться.
      next: neighbours_angry
    choices:
      - id: polite_rule
        text: "«Прошу Вас прекратить курение. В поезде это не допускается — это вопрос безопасности движения»"
        quality: best           # best | good | poor | bad
        role_model: [rule]      # acknowledge | rule | solution | assure
        effects: { safety: 15, loyalty: -5 }
        feedback: Вежливо и с акцентом на безопасность — как требует регламент.
        next: passenger_reacts
      - id: ignore
        text: Сделать вид, что не заметили
        quality: bad
        effects: { safety: -20 }
        feedback: Курение на борту — угроза безопасности движения, игнорировать нельзя.
        next: neighbours_angry
  passenger_reacts:
    type: router                # невидимый узел — выбор ветки по состоянию
    routes:
      - if: ["loyalty >= 60"]
        next: passenger_agrees
      - next: passenger_refuses # последний маршрут без if — «иначе»
  end_ok:
    type: ending
    outcome: success            # success | partial | fail
    title: Нарушение прекращено
    text: Пассажир убрал устройство, в вагоне спокойно.
```

## Поля узла `choice`

| Поле | Обяз. | Описание |
|---|---|---|
| `text` | да | Ситуация или реплика собеседника |
| `speaker`, `speaker_name` | нет | Кто говорит (для интерфейса) |
| `competencies` | да | Какие компетенции проверяет это решение (коды из `content/competencies.yaml`) |
| `timer` | нет | Секунды на решение. Сервер сам проверяет время ответа (+2 с на сеть) |
| `on_timeout` | если есть `timer` | `effects`, `feedback`, `next` — что происходит при бездействии |
| `choices` | да, ≥ 2 | Варианты ответа |

## Поля варианта ответа

| Поле | Обяз. | Описание |
|---|---|---|
| `id` | да | Уникален в пределах узла |
| `text` | да | Действие или реплика проводника |
| `quality` | да | `best` / `good` / `poor` / `bad` → 1.0 / 0.6 / 0.2 / 0 в подсчёте компетенций |
| `feedback` | да | Объяснение для разбора: почему так / чем плохо |
| `next` | да | Следующий узел |
| `effects` | нет | `loyalty`, `safety` (прибавка, итог ограничивается 0..100), `vars` (прибавка), `flags` (установка true/false) |
| `role_model` | нет | Шаги ролевой модели, которые реализует реплика |
| `if` | нет | Условие доступности: вариант показывается, только если условие истинно |

## Условия

Условие — список строк, **все** должны быть истинны (логическое И). Логическое ИЛИ — несколько маршрутов `router`.

Строка — ровно три части через пробел: `<операнд> <оператор> <значение>`.

| Операнд | Значение |
|---|---|
| `loyalty`, `safety` | текущие шкалы |
| `vars.<имя>` | переменная сценария (должна быть объявлена в `initial.vars`) |
| `flags.<имя>` | флаг (по умолчанию `false`) |
| `class` | класс обслуживания сценария |

Операторы: `<`, `<=`, `>`, `>=`, `==`, `!=`. Значение: число, `true`/`false` или слово (`business`).

Примеры: `"safety < 40"`, `"flags.chief_called == true"`, `"vars.minutes_to_station <= 3"`, `"class == first"`.

## Что проверяет валидатор

- `start`, все `next` и `interrupts[].next` ссылаются на существующие узлы;
- каждый узел достижим из `start`, и из каждого узла достижим хотя бы один `ending`;
- у `choice` не меньше 2 вариантов, `id` уникальны; при `timer` задан `on_timeout`;
- у `router` последний маршрут — без `if` (ветка «иначе»);
- условия корректны синтаксически, переменные объявлены, компетенции существуют;
- ни один переход не оставлен пустым («не указано, куда ведёт переход»).

Каждая проблема привязана к узлу (`node_id`), поэтому редактор подсвечивает конкретный узел.

## Служебное поле `layout`

Необязательное поле с позициями узлов в визуальном редакторе: `layout: {start: {x: 0, y: 0}, ...}`.
На игру не влияет; его записывает редактор, вручную заполнять не нужно.

## Живое изменение на защите — рецепты

1. **Изменить правило шкалы:** поменять `effects` у варианта (например, `safety: 15` → `safety: 5`).
2. **Добавить развилку:** добавить вариант в `choices` с `next` на новый узел, описать новый узел.
3. **Сделать ветку условной:** добавить `if: ["loyalty >= 50"]` к варианту или новый маршрут в `router`.
4. **Ужесточить таймер:** поменять `timer`.

После правки: увеличить `version` и перезапустить backend (или загрузить файл через `POST /api/v1/scenarios`).

**То же в визуальном редакторе:** открыть сценарий → кликнуть узел → поменять эффект / добавить вариант и протянуть
связь от его точки к узлу (или на пустое место — появится новый узел) → «▶ Прогон» → «Опубликовать».
Версия увеличивается автоматически.
